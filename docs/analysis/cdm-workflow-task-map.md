# CDM collateral workflow → task map

Part of `investigation-cdm-workflow-task-map` (goal `goal-end-to-end-flow`). One row per collateral workflow that this
repository's analysis identifies, with its CDM status, the prototype flow that implements it (the CDM workflows in
[`architecture/prototype.architecture.json`](../../architecture/prototype.architecture.json), written in CALM), what
is built, and the task that closes what is missing.

Sources: [`cdm-csa-coverage-matrix.md`](cdm-csa-coverage-matrix.md),
[`cdm-other-agreements-coverage-matrix.md`](cdm-other-agreements-coverage-matrix.md),
[`findings.md`](findings.md), [`collateral-conceptual-model.md`](collateral-conceptual-model.md),
[`collateral-flows.md`](collateral-flows.md), [`business-case.md`](business-case.md) and the gap register
[`gap-register.md`](gap-register.md) (gap IDs G1–G41). Implementation status is
as of 2026-11-22 (`main` after PR #92, release `v0.2-demo`): every row of sections A, B and C is built, and the full live suite (57 specs) passed locally on a reset chain after PR #89; PR #90 then changed `flow-registered-collateral-gmsla`.
Since `v0.1-demo` (`goal-tokenized-collateral`) the rows that move a Registered or Claim token (tMMF) complete on the record keeper's confirmation, and the rows where a party takes tUST or tMMF as collateral apply the provenance gate; the changes are listed in [`../releases/v0.2-demo.md`](../releases/v0.2-demo.md).

Build order, set by the project owner on 2026-11-03: the ISDA CSA cycle first (sections A and B), then the four other
agreement families (section C). Section B starts only after the rest of section A is done: `flow-oracle-update`,
`flow-revaluation-top-up` and the valuation gaps G7–G10 (`nw-core-cycle-first`, project owner). The order of the
rows in section B (`nw-csa-extension-order`) and section C (`nw-agreement-family-order`) was proposed by the
maintainer and accepted by the project owner (2026-11-03).

Every section uses the same columns:

- **#**: the row's number in its section: the order of the margin cycle in A, the build order in B and C.
- **Workflow**: the collateral workflow.
- **CDM status**: what CDM 7.7.0 covers, with the gap IDs of what it lacks (gap register; scores from the coverage
  matrices where they exist).
- **`cdm-ext`**: what the local extension adds over CDM 7.7.0.
- **Prototype**: the prototype flow and what is built (contracts, gateway, services, console).
- **Live spec**: the Playwright test in `console/e2e/live.spec.ts` that asserts on-chain state through the gateways.
- **Task**: the task that builds the row or closes what is missing.
- **PR**: the pull request that added the row's prototype flow and live spec; — when the row is not built.
