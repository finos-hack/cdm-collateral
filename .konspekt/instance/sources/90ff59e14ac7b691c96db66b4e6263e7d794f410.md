Question: scripts/live-e2e.sh starts about a dozen node.js processes, 4–5 JDKs, Docker and WSL on your machine. Why?

Cause: this is the process layout orchestrate.mjs is written to start.

Node (about 11–12): orchestrate.mjs, the store, 4 gateways (bank-a, bank-b, bank-c, mkt), the console (npm plus Vite), and during check the npx/Playwright runner and its workers.
Java (4): the oracle plus the collateral services A, B and T. The 5th JDK is not started by this repo. It is likely Maven or an IDE language server (unverified).
Docker/WSL: the 4 Besu validator containers, running inside Docker Desktop's WSL 2 VM.

What the repo shows:

The run log in docs/runbook-e2e.md records you running the stack on the Windows 11 host from Git Bash. On Windows, spawn(..., { shell: true }) adds a cmd.exe wrapper for each child.
shutdown() kills only that wrapper, so stopping orchestrate.mjs with Ctrl-C can leave orphaned node/java processes. up and down clear them by port.
The accepted ADR wp-adr-per-participant-services requires one stack per participant, with each keystore holding only its own key. Merging the gateways or the Java services into one process would mean revising that ADR.
The code already differs from that ADR in two places: one store process and one console dev server serve all parties.
No konspekt record says whether the concern is memory or process count.

Options that need no ADR change:

Cap the JVM heap with JAVA_TOOL_OPTIONS.
Fix the Windows process-tree kill in shutdown().
Run the stack in the repo's dev container, so all node/java processes move inside it.
