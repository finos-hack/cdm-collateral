> moving parts - the chain, UI app, rudimentary datastores - all wired together.

  sub-tasks (which you might) create them".
- Workflow-layer language for the first cycle: **Java Javalin now** (honors ADR
  `wp-adr-java-cdm-stack`).
- UI surface for the first cycle: **Wire the existing React console**.

## Maintainer (verified outcome)

Stood up one complete cycle of `flow-im-margin-call-pledge` (full-agreement,
single-token happy path), bank-b secured party and bank-a pledgor, across all
layers:

- Besu QBFT network (4 nodes) running; contracts deployed and the three test
  tokens (tUST, tMMF, tUSD) tokenized on-chain with ISIN/CUSIP/DTI; registry at
  `contracts/deployments/besu.json`.
- Ledger gateway (`gateway/`, TypeScript + viem), one instance per participant,
  signing with that party's Besu node key; HTTP API `/ledger/v1`.
- Collateral workflow service (`services/collateral/`, Java 21 + Javalin), one
  instance per participant, SQLite workflow store, HTTP client to the gateway;
  REST API `/api/v1`.
- React console wired in live mode (`console` route `#/live/A|B`,
  `src/components/LiveConsole.tsx`, `src/domain/liveApi.ts`), driving the
  lifecycle against the live services.

Verified: the gateway cycle runner asserts on-chain settlement (call settled,
proposal accepted, 60,000 tUST escrowed, pledgor balance reduced); the full
cycle also runs through the service REST API; and a Playwright live test
(`console/e2e/live.spec.ts`) drives issue → agree → propose → accept → pledge
through both wired consoles and asserts "settled on-chain" in both.
