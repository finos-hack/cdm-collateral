## Maintainer

Scope for `task-ci-live-e2e-stack`: run the single live flow `flow-im-margin-call-pledge` (the one the harness `console/e2e/live.spec.ts` already drives — issue → agree → propose → accept → pledge, settled on-chain), but run it completely in CI rather than skipping it. The gap between the current `console.yml` job (Node-only: npm ci / typecheck / test / build / playwright, console/ only) and what the live spec's health guard (`fetch http://localhost:8001/api/v1/context`, else `test.skip`) requires is these eight steps:

1. Docker + Besu QBFT bring-up — start `besu/docker-compose.yml` and wait for the network.
2. cdm-ext install — `mvn install` of `cdm-ext/` so `local.cdmx:cdmx-java` is in the local Maven repo before the collateral jar builds.
3. JDK 21 + Maven setup and collateral jar build — `mvn -DskipTests package` in `services/collateral/`.
4. Contracts install + deploy — `npm ci` in `contracts/` then `npm run deploy:besu`, producing `contracts/deployments/besu.json`.
5. Gateway and store installs + startup — `npm ci` in each of `gateway/` and `store/`, then launch the five backend processes with the per-party store tokens.
6. Non-interactive orchestration — `orchestrate.mjs` is local-only (also starts the console dev server on 5173 and blocks on SIGINT); CI needs background startup, a readiness wait on 8001/8002, then teardown.
7. Guard against silent green — the spec skips (not fails) when 8001 is unreachable, so CI must assert the stack it started is reachable, or a failed bring-up passes.
8. Separate workflow/job with a broader path filter — covering `besu/**`, `contracts/**`, `gateway/**`, `store/**`, `services/**`, `cdm-ext/**`, not just `console/**`.

The full `task-e2e-wiring` surface (oracle service, other agreement families, per-party stores) stays out of scope; this task runs only the one flow the live spec asserts, end to end.
