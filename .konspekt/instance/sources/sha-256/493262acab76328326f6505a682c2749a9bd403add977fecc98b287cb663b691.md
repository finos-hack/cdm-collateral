## Maintainer

Open items:
1. **Where the repos live.**
   - (a) Recommended: each repo is a CDM `TradeState` built from CDM's repo samples and held by both services off-chain. Purchase and repurchase settle on-chain as delivery versus payment (security token against tUSD). The trade events that change a repo (reprice, adjustment, roll, pair-off, substitution) run through CDM's own functions; the chain records each event's hash and any transfer it causes.
   - (b) Trades off-chain only; the chain carries only margin transfers.
   - (c) Repo trades held on a new contract.
2. **Margin transfer (GMRA paragraph 4).**
   - (a) Recommended: outright title transfer of cash or securities through the `MarginCall` contract and the VM settlement path. The call amount is the pair's Net Exposure across all repos once it passes the minimum transfer amount. Reprice and adjustment are the alternative ways to settle that exposure, chosen per call.
   - (b) Settle exposure only by reprice or adjustment.
3. **GMRA terms (G20).**
   - (a) Recommended: a `cdm-ext` type holding the Annex I elections the ten workflows need: Margin Ratio basis, minimum transfer amount, margin transfer method, Net Margin interest, the income payment rule, and the default valuation terms. The amendment workflow (G19) then changes these terms the same way the CSA amendment does.
   - (b) Only the elections margin maintenance needs, added to as each workflow is built.
4. **Defect D2 (the margin ratio is defined as market value ÷ purchase price but applied as a multiplier).**
   - (a) Recommended: correct it in `cdm-ext`, as was done for D1, with tests.
   - (b) Use CDM's function as is and note the defect.
5. **Directions and buy/sell-back.**
   - (a) Recommended: A and B can each be buyer or seller, so the pair has repo and reverse repo between them, and Net Exposure nets across both directions. Buy/sell-back is a trade type on the same flows, with its own `cdm-ext` qualification and economics (G33).
   - (b) One direction only, A as seller.
6. **Process.**
   - (a) Recommended: as in section B. First a scope ADR (proposed), then one task per workflow under `task-repo-gmra-workflows` in build order, each with its own live spec. The task map's section C gets one row per workflow.
   - (b) One task for the whole family.
