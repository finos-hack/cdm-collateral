## Open items

Row 19 design choices. Option (a) is the one I recommend in each case.

1. **How a default starts:** (a) As for repo: the oracle's default record, then a Default Notice from the party not in default. No notice is needed if automatic early termination applies, but the baseline has it off. (b) Automatic termination only.
2. **New CDM extension types:** (a) New GMSLA types (`GmslaDefaultNotice`, `GmslaDefaultLoanValue`, `GmslaCloseOutStatement`) in the GMSLA extension, reusing `GmraDefaultMarketValue`. (b) Make the repo types generic and share them between both agreements.
3. **What each loan is worth at close-out:** (a) The lender is owed the loaned quantity still out x the oracle price. The borrower is owed its collateral back: cash at face value, tUST x its oracle price. (b) Use the booked price instead of the oracle price.
4. **Fee or rebate earned but not yet paid** (from the billed-through date to the Early Termination Date, plus any unpaid invoice): (a) Include it in the net balance, worked out as in rows 17/18. (b) Leave it out.
5. **Margin held under the row 14 GMSLA margin calls:** (a) Include it and offset it, as for repo. (b) Leave it out.
6. **What moves on settlement:** (a) No securities or collateral move. The loans close, and one net balance is paid in tUSD by whichever party owes it. (b) Return the collateral first, then net the rest.
7. **Contract:** (a) Give `SecuritiesLoan` a link to the oracle and a `closeOutDefault` function. This needs a redeploy. (b) A separate close-out contract.
8. **Repo and loans with the same counterparty:** (a) One statement per agreement, so a GMSLA close-out next to the repo one. (b) One combined statement.
9. **Console and test:** (a) A "Close out" action in the Loans card once the counterparty is in default, as for repo. (b) API only. Either way, the live spec `flow-gmsla-default-close-out` restores the default status afterwards.
